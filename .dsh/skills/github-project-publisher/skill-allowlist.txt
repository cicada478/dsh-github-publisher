# ---------------------------------------------------------------------------
# skill 自带豁免清单 —— 只针对 **skill 自身的文件**
#
# 为什么这份清单在 skill 里，而不是在宿主项目里
# --------------------------------------------
# skill 自己的规则定义与自测里必然出现"看起来像密钥"的字符串。如果这只能由
# 宿主项目来豁免，那么任何**项目级安装**本 skill 的仓库都会收到一批误报——
# 实测 57 条 BLOCKER，全部来自 skill 自身文件，而那个仓库并没有做错任何事，
# 也没有立场替别人的文件写豁免。
#
# 因此把「skill 自己的豁免」放进 skill，随它一起分发。
#
# 条目格式与宿主项目清单完全相同
# ----------------------------
#   <规则ID>  <路径通配>  <行号|*>  -- <理由>
#
#   理由必填，且必须由条目自身给出（行内 `--` 之后）。无理由的条目会被拒绝，
#   并作为问题报告。每条生效的豁免都会写进报告，并标明来源（skill / project）。
#
# 路径为什么写成 `*/github-project-publisher/scripts/...`
# ---------------------------------------------------
#   skill 可能被装在 <项目>/.dsh/skills/、~/.dsh/skills/ 或任一 customSkillDirs
#   下。用前缀通配才能在任何安装位置命中，而不必知道它装在哪里。
#
# 这不等于"整份文件豁免"
# --------------------
#   条目按 **规则 + 路径** 生效，不是"跳过这个文件"。其他规则在这两个文件里的
#   命中一律照常上报；报告里也会逐条列出被豁免的内容与理由。
#
#   剩余局限（已知，未消除）：同一规则在同一文件里的**新增**命中也会被覆盖。
#   要消除这一点需要按内容指纹豁免（类似 .gitleaksignore 的做法），属于后续改进。
# ---------------------------------------------------------------------------
