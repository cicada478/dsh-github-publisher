# 敏感信息扫描豁免清单
#
# 加条目的判据——必须同时满足
# --------------------------
#   a. 该命中**确实不是**敏感信息，而不是「我希望它不是」
#   b. 无法用公认占位形式（example.com / your_ / <...> / xxxx 等）消除
#   c. 能写出一句经得起 review 的理由
#
#   不满足任何一条时，正确的做法是**改文档**（把真实值换成占位形式），
#   而不是在这里加豁免。豁免是逃生口，不是常规手段。
#
# 格式
# ----
#   <规则ID>  <路径通配>  <行号|*>  -- <理由>
#
#   理由为必填，且必须由该条目自身给出：行内 `--` 之后，
#   或紧邻上方以 `# reason:` 开头的注释行。
#   **普通的 `#` 注释不构成理由**——否则文件头注释迟早会被当作理由，
#   「理由必填」这条约束就会形同虚设。
#
#   无理由或格式错误的条目会被**拒绝**，并作为问题报告出来。
#   每一条生效的豁免都会写入审计报告，含规则、路径、行号与理由原文。
#
# 为什么本清单现在非空
# --------------------
# 本清单此前为空，而扫描器改用一份**按文件名整份豁免**的硬编码旁路
# （`_common.py` 的 SELF_SCAN_FILENAMES）来放过自身与自测里的字面量。
# 那是错的：实测该旁路静默吞掉了 112 条命中，其中 4 个被豁免的文件里有 2 个
# （`_common.py`、`audit_repo.py`）本来就一条都不产生，而报告却写着
# “并未跳过这些文件”。真实密钥若误入这些文件会被无声放过。
#
# 现在改为：硬编码旁路只保留给**真正的正则字面量**（需命中文本含正则元字符），
# 其余一律照常上报，再由本清单**逐条显式豁免并写明理由**。
# 下面这些条目就是那条路径的全部产出——它们是可见的、有理由的、进报告的。
#
# 依据：references/checks.md 第 4 节
# ---------------------------------------------------------------------------
